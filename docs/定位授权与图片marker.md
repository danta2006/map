# 定位授权 & 图片 Marker 说明

> 记录两件事：① `wx.getLocation` 的接口权限怎么申请、没开通时演示怎么办；② 以后照片到位了，图片 marker 怎么做。

---

## 一、`wx.getLocation` 有三层门槛，别混

| 层 | 在哪配 | 现在状态 |
|---|---|---|
| 1. 代码声明 | `app.json` 的 `requiredPrivateInfos: ["getLocation"]` | ✅ 已配 |
| 2. 用户授权 | 运行时弹窗（`scope.userLocation`），拒绝后走 `wx.openSetting` | ✅ 已配（`permission.scope.userLocation` 的说明文案） |
| 3. **接口权限开通** | 小程序后台「开发管理 → 接口设置」 | ⬜ 未申请（**这层决定能不能提审上线**） |

第 3 层要开通，前置条件是**服务类目审核通过**，并且类目在官方开放清单里。

---

## 二、怎么申请（按顺序做）

### 1. 先确认主体和类目

官方开放类目里跟我们最贴的两行：

| 一级类目 | 二级类目 | 官方给的应用场景 |
|---|---|---|
| 旅游 | 景区服务、住宿服务 | 提供景区导航、导览服务、酒店导航服务 |
| 工具 | 信息查询、办公、设备管理、天气 | 与地理位置相关的服务，比如…**与地理位置相关的打卡服务** |

- **企业 / 学校主体**：选「旅游 → 景区服务」最贴，一次到位
- **个人主体**：选不了旅游类目，只能走「工具 → 信息查询」，场景描述往"景区打卡 / 附近点位导航"上靠

### 2. 后台操作路径

```
微信公众平台 → 设置 → 基本设置 → 服务类目
  → 添加「旅游-景区服务」或「工具-信息查询」
  → 提交审核（要写使用场景说明）

类目审核通过后：
开发 → 开发管理 → 接口设置
  → 找到「获取当前的地理位置、速度」→ 申请
  → 使用场景填：用户在景区附近打卡、显示到景点的距离、路线导览
```

### 3. 审核要点（容易被驳回的地方）

- **类目要匹配**：用「工具-信息查询」申请时，场景说明必须写清"与地理位置相关的打卡/导航"，别写成单纯的资讯查询
- **不能有其它定位用途**：比如"附近的人""获取用户轨迹"，写了就废
- **时间**：类目审核 1–3 个工作日，接口开通一般也是 1–3 个工作日

### 4. 提审时会被查什么

2022-04-18 起，代码审核会检查：
1. `app.json` 是否声明了 `requiredPrivateInfos`
2. 接口是否已在后台开通

缺一个就被拦。所以**先开通、再提审**。

---

## 三、没开通时怎么演示（重要）

我们项目是**大创作品，不打算上线**，所以第 3 层不申请也不影响演示：

| 场景 | 能不能定位 | 说明 |
|---|---|---|
| 开发者工具 | ✅（模拟定位） | 工具里用 IP 定位，误差可能几百米；左下角可手动设模拟定位 |
| 真机 + 开发版/体验版 | ✅（弹授权） | 首次进详情页或点「定位」会弹授权框；**接口权限没开通时部分机型会直接 fail** |
| 真机 + 正式版 | ❌ | 没开通权限，上线后调用会失败 |

**兜底已经做好**：

- 详情页/面板里「距你」拿不到定位时显示「定位没打开」，按钮仍是可点的
- 打卡：范围内直接成功；范围外弹窗可选**手动打卡**；拒绝授权也一样能手动打卡
- 演示前建议：真机上提前把定位权限打开，用体验版演示

> 如果答辩当天定位抽风，直接走手动打卡，逻辑和记录都在，不影响讲"打卡"这个功能点。

## 四、图片 Marker（已完成：2026-10 抓取 45 张）

现在每个点位已经是**圆形实景图 marker**（分类色环）+ 详情页大图，来源见下。

### 0. 照片来源与版权

- 用 `scripts/fetch_photos.py` 从高德「地点搜索」的 `photos` 字段抓的（每个点位取第 1 张）
- **仅限课程/大创演示使用**；如果以后要公开发布或商用，必须换成自己拍的或取得授权的图
- 抓取结果：45/45 成功（窑湾、十八总米粉、灯芯糕、黄兴南路 4 个用了别名补抓）

### 1. 素材怎么收

| 项 | 要求 |
|---|---|
| 数量 | 每个点位 1 张，`<点位id>.jpg`（id 见 `miniprogram/data/places.js`） |
| 内容 | 该点最有辨识度的一角（门头 / 主建筑 / 招牌菜），主体居中 |
| 尺寸 | 长边 1024 左右，JPG，质量 80 即可 |
| 存放 | 收到 `assets/photos-src/`（这个目录不打包） |

### 2. 处理脚本

```powershell
python scripts/make_photo_markers.py
```

它会：
- 读 `assets/photos-src/<id>.jpg`
- 中心裁成正方形 → 缩到 96×96 → 圆形裁剪 → 加白边 + 分类色环（和现在 marker 同色）
- 输出到 `miniprogram/assets/photos/<id>.png`
- 最后打印每张大小和总大小

### 3. 包体估算（主包上限 2 MB；当前含图约 1 MB）

| 点位数量 | 96×96 PNG 总量 | 结论 |
|---|---|---|
| 45（现在） | 约 300–450 KB | 直接放主包，没问题 |
| 150（三城各 50） | 约 1 MB | 还能放，接近上限 |
| 200+ | 1.5 MB+ | 建议上云存储 / CDN（要域名白名单，个人主体受限） |

### 4. 地图上怎么切

- 缩放 < 13.5：还是现在的彩色 pin（远看只区分类型）
- 缩放 ≥ 13.5 且不重叠：换成图片 marker（同一个阈值逻辑，复用 `applyBubbles`）
- 详情面板顶部：换成大图（现在是一块分类色 + emoji）

### 5. 工作量

| 事项 | 时间 |
|---|---|
| 处理脚本 | 已完成（`scripts/make_photo_markers.py`） |
| 地图 marker 切换逻辑 | 约 1 小时（照片到位后我接） |
| 详情面板大图 | 约 0.5 小时 |
| 照片采集 | 团队现场拍，45 张约半天 |

### 6. 兜底

没有 `photo` 字段的点位，继续用现在的彩色 pin + emoji 气泡，不影响地图功能——所以可以先给一部分点配图，逐步替换。
