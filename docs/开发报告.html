1. 项目概述

1.1 目标

做一个能在一张地图上把长株潭值得去的点标出来的小程序：点开有攻略、能按精选路线逛、到了能打卡，还能自己拼一条「我的行程」。

不做第二个大众点评，只保证三件事：点是真的、路线是能走的、演示是稳的。

设计取舍：小程序端读打包进去的静态数据（而不是运行时请求后端），原因有三——

  1. 个人主体无法备案 HTTPS 域名，真机请求外部接口会被拦；
  2. 静态数据首屏无网络依赖，演示最稳；
  3. 内容生产用本地后台，改完导出即可，不需要运维服务器。

云开发只承担「真机收集反馈」这一件事（云数据库不需要域名备案）。

3.2 地图首页（pages/map）

职责：总入口。看全城点位、切城市、筛分类、看点位卡片、进入详情或行程。

功能 实现方式
点位标记 map 的 markers，按分类取不同 pin 图，callout 显示名称（点击显示）
分类筛选 6 个 chip（全部/景点/古镇街区/红色/学府/美食/酒店），带分类色点当图例
城市切换 左上角城市 pill，下拉面板，切城市同时换 center/scale 与点位
点位卡片 底部卡片（名称/分类/时长/一句话/备注/导航），点卡片进详情
上滑详情面板 卡片可上滑展开整页详情（简介/地址/开放时间/距你/打卡），也可下滑收起
实景图气泡 缩放 ≥13.5 且与相邻点位屏幕间距 ≥128px 时，点位上方浮出圆形实景图气泡
加入行程 列表卡片右上「＋」、面板标题「＋ 行程」
搜索 右上 🔍 打开浮层，边输边出结果，结果先出介绍卡片再决定加入
定位 右下 ◎ wx.getLocation + mapCtx.moveToLocation

关键技术点

  1. 气泡（customCallout）：用 map 的 <cover-view slot="callout"> + marker-id 绑定；显隐用 marker.customCallout.display。
    • 气泡尺寸 96rpx 圆形，anchorX/anchorY 控制位置（文档语义：向右/向下为正）；
    • 当前取值 anchorX:6 / anchorY:10，即正对图钉上方且底边贴住钉帽；
    • 坑：customCallout 改变后地图不会自动重绘，必须把 markers 清空再写回强制重建；
    • 气泡本身也绑了 bindtap，点气泡等于点图钉。
  2. 点击命中：bindmarkertap（点图钉）、bindcallouttap（点原生气泡）、bindtap（空白处关闭），三者用 200–350ms 时间窗互斥，避免「卡片刚弹出就被关」。
  3. 抖动治理：地图中心/缩放不做 regionchange 回写（早期回写会导致拖动后地图自己跳），只在切城市/切分类/定位时主动设置；气泡重算用「显示集合 key 去重」，集合没变不 setData。
  4. 城市切换：CITIES 配置三城中心与缩放，切城市同时过滤点位、重置分类、收起卡片。

3.3 我的行程（pages/trip）

职责：用户自选点位拼行程，看总耗时/里程、调顺序、切交通方式、看打卡进度。

数据模型

// utils/trip.js，存 wx.storage: { ids: [...], modes: { 'a|b': 'walk'|'transit'|'taxi' }, updatedAt }
能力 实现
加点 / 移点 地图页「＋」、详情页头图「＋ 加入行程」、行程页搜索框；同一点位再点即移出
排序 长按 260ms 进入拖动，整个「站点块（站点 + 该段交通）」跟手移动，松手按最近块落位；也可用 ▲▼
地图绘制 编号 marker（1..N）+ 每段按交通方式着色的双层折线（白描边 13 + 主色 8）
交通耗时 每段列步行 / 公交地铁 / 打车三种时间，点选切换；有实测标「实测」
时间与里程 顶部统计：点位 / 游玩 / 在途 / 里程；里程用各段真实距离累加
打卡进度 「已打卡 N/M」+ 进度条 + 每个已打卡站点 ✓（读 checkin_<id> 记录）
面板 默认收起（只留底部一条），点开半屏（42% 屏高），可拖到全屏/隐藏
点路线弹卡 点折线附近、点两站之间的时间图标都能弹该段卡片，三种方式直接切

交通时间的三级数据源（utils/travel.js）

  1. 精选路线里出现过的点对 → 直接用 routes.js 里高德返回的实测（realSource: 'route'）；
  2. 同城 ≤8km 的其他点对 → 预计算的 data/realLegs.js（283 对，覆盖率 93%）；
  3. 其余 → 直线距离 × 道路系数 1.28 + 各方式速度折算，界面标注估算。

跨城处理：两点不同城时，步行禁用（显示「跨城不推荐」），公交按城际列车估算（距离/1500 m/min + 30min），打车按高速估算（距离/700 m/min + 5min）；折线不画，改在中点标「跨城 XX 公里」。

3.5 点位详情（pages/detail）

结构：头图（实景图 + 渐变遮罩，无图退化分类色块）→ 事实信息（分类/地址/开放时间/建议时长/距你）→ 关于这里 → 备注或补充 → 反馈链接 → 底部「导航 / 到这里打卡」。

打卡规则（data/places.js 的 CATEGORY_RADIUS，单点可用 radius 覆盖）

分类 半径 理由
学府 1500 m 一座校园从南门到北门就一公里
红色 1200 m 韶山冲这类成片景区
古镇街区 800 m 成片区域不是一个点
景点 600 m 一栋楼、一座公园
美食 / 酒店 300 m 到店门口

状态机：范围内直接打卡；范围外弹窗可选手动打卡；无定位引导设置或手动；>30km 额外提示疑似模拟定位。记录：{ at, distance, manual }。

3.6 反馈页（pages/feedback）

6. 质量保障

6.1 静态检查（scripts/check_pages.js）

对每个页面检查：

  1. WXML 里绑定的事件（bindtap/catchtap/bindtouchmove 等）在 JS 中是否有对应函数；

这个脚本是因为一次误删 toggleCityPicker 导致「点城市按钮没反应」才加的，现在是上传前必跑项。

7. 已知限制

  1. 没有运行时后端：小程序读静态数据，改内容要重新导出、重新上传体验版（这是为绕开备案域名做的取舍）。
  2. 个人主体限制：不能选「旅游-景区服务」类目，不能发布上线；wx.getLocation 正式接口权限未申请，真机依赖授权弹窗与手动打卡兜底。
  3. 图片版权：45 张实景图来自高德 POI，仅限课程演示，商用/公开发布需替换为自有素材（替换流程已脚本化）。
  4. 交通时间为静态预计算：不含实时路况，早晚高峰驾车会偏乐观；跨城时间为估算。
  5. 云开发为免费试用：到期需续费（¥19.9/月）或迁回本地，数据在环境内。
  6. 6 家酒店暂无实景图（气泡退化为分类 pin）。
  7. 我的页 / 足迹页未做：打卡记录只在本机，未做汇总页。
  8. 后台无鉴权：仅限本机使用，不能部署公网。
