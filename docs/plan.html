01

一页结论

给没时间看全文的人
把湘潭的景点、美食、老街，从"一篇文章"变成"地图上一个个能点开的点"，再串成能照着走的路线。 —— 产品定位，也是答辩开场那句话
做什么
湘潭地图 + 30 个可点开点位 + 3 条精选路线 + 到点打卡足迹
不做什么
社区/UGC、评论、支付、多城市、后台管理、个性化地图
技术栈
微信原生小程序（JS）+ 内置 map 组件，不上框架、不上构建链
数据
POI 打包成本地 places.js；图片走云存储；打卡记录走云数据库
后端
云开发，但零云函数：集合权限"仅创建者可读写"，自动带 openid
复用基座
map-marker-miniprogram（Apache-2.0）为主，省 2–3 天

成功标准只有一句：真机打开 → 地图有 30 个点 → 筛选 / 点开 / 详情 / 导航全通 → 路线能看 → 打卡能记。

开工前先知道三个坑
类目个人主体选不了「旅游-景区服务」，别指望上架；开发版 / 体验版 + 投屏答辩。
定位wx.getLocation 要在后台申请、可能不批；手动打卡降级是必做项。
包体主包 2MB，60 张图必超；图片全部走云存储。

02

功能范围

严格分级，防范围蔓延

12 天最大的敌人不是技术，是"再加一个功能"。所以先划死线：P0 做不完，P1 直接砍。

P0 · 必须做 11/5 前跑通

答辩就靠这 7 项，一个都不能少

  • 地图首页：湘潭全域，30+ marker，按分类换图标
  • 六分类筛选：全部 / 景点 / 美食 / 古镇街区 / 红色 / 学府
  • 点 marker 弹底部卡片（图 + 名 + 一句话）
  • 详情页：图 / 简介 / 地址 / 开放时间 / 建议时长 / 本地提示 / 导航
  • 路线页：3 条路线，polyline + 序号 marker + 点位列表
  • 打卡：定位 500m 内可打 → 写云数据库 → 我的页足迹
  • 我的页：打卡数 / 完成度 / 足迹列表

P1 · 有余力再做

11/6–11/7，做不完就砍

  • 本地搜索点位
  • 收藏
  • 分享卡片
  • 天气
  • 打卡徽章规则
  • 路线进度条

P2 · 明确不做

别碰，碰了就延期

  • UGC 发布 / 评论
  • 点赞关注
  • 支付 / 预约
  • 后台管理系统
  • 多城市扩展
  • 个性化地图样式
  • 真实登录体系
砍功能原则 任何一项 11 月 4 日还没开工，直接进 P2。宁可 5 个页面完整，不要 9 个页面半成品——答辩老师看的是完整度，不是功能数量。
03

技术方案

怎么搭，为什么这么搭
视图层WXML / WXSS
3 tab + 2 详情页
一套 design tokens
地图内置 <map>
markers + 气泡
polyline + 导航
数据层本地 JSON
places.js / routes.js
零延迟、免分页
云云开发
checkins 集合 + 云存储
零云函数

为什么是这套

选择理由
原生小程序，不用 Taro / uni-app12 天不够踩框架编译坑。原生 + 内置组件是故障面最小的路径。
不引入 npm 构建链少吃一类"构建失败 / 依赖版本冲突"的亏；Vant 之类按需再上。
不做个性化地图subkey 2023-06 起要在后台付费购买、工具内不能调试、只能真机验证。默认样式 + 自绘 marker 已经够好看。
POI 不进数据库客户端查库默认只回 20 条，60 条要分 3 页拉——纯属自找麻烦。本地 JSON 55KB，require 即用。
打卡不用云函数checkins 权限设"仅创建者可读写"：查询自动过滤成自己的记录，写入自动带 _openid。省掉云函数、登录、token。
不调腾讯地点搜索 API免费额度每日仅 200 次，还要配合法域名。搜索走本地过滤，够用且零风险。
路线折线离线生成跑一次脚本存进 routes.js，运行时零 API 调用。手绘 8–12 个拐点都够看。

三个必须做对的细节

  1. 气泡别全开 用 <cover-view slot="callout" marker-id>。首页只给 3–5 个重点位设 ALWAYS，其余 BYCLICK——30 个气泡同时展开会糊成一片。
  2. 打卡一定要有降级 定位权限可能申请不下来。失败时按钮变成「我到过这里（手动打卡）」，答辩现场就靠这个兜底，不能等到上台才发现。
  3. 所有数据都要有兜底 云开发挂了 → 打卡写 wx.storage 合并展示；图片 404 → 灰底占位；无网络 → 友好提示不白屏。这三种状态必须各留半天做。

页面结构

pages/
├─ map/          地图首页（tab1，核心，占 40% 工作量）
├─ routes/       路线页（tab2）
├─ mine/         我的 / 足迹（tab3）
├─ detail/       点位详情（非 tab）
└─ route-detail/ 单条路线详情（非 tab，地图模式）
components/
├─ poi-card/     POI 卡片（地图底部卡片、列表复用）
└─ tag-bar/      分类筛选条（复用）
data/
├─ places.js     30–60 个点位
└─ routes.js     3 条路线的折线坐标

只做 3 个 tab。第四个 tab（发现/攻略）砍掉——和地图内容高度重复，删了不影响演示。

数据方案

大创的核心竞争力，也最耗时间

目标：P0 30 个点（撑满地图、够 3 条路线），冲刺 60 个；3 条路线，每条 5–7 个点。

先定名单，再补坐标

分类点位
景点 / 古迹万楼、观湘门、文庙、海会古寺、大唐兴寺、天主堂、昭山、白石公园、雨湖公园、和平公园、菊花塘公园、湘潭之光、望衡亭
古镇 / 街区窑湾古镇、十八总、杨梅洲、莲城步行街、万达广场、步步高广场
红色韶山毛泽东故居、铜像广场、纪念馆、滴水洞、韶峰、乌石彭德怀故居
学府湘潭大学、湖南科技大学、湖南工程学院
美食灯芯糕、脑髓卷、湘潭米粉、毛氏红烧肉、槟榔、湘莲、火焙鱼（挂到具体店铺/街区）

30 个 P0 点建议配比：景点 12 + 古镇街区 6 + 红色 6 + 学府 3 + 美食 3。

字段设计（data/places.js）

五步采集

  1. 定名单0.5 天，确认 30 个 P0 点。
  2. 拿坐标0.5 天。用腾讯位置服务「坐标拾取器」手工点，30 个约 1.5 小时，最稳。别在小程序里调地点搜索 API（200 次/日）。
  3. 写文案1.5 天，每人 10 个点。文案质量决定答辩观感，别抄百科。
  4. 配图1 天。统一裁 4:3、压到 150KB 内，传云存储；places.js 只存 fileID。
  5. 转 JSON0.5 天。Excel 维护 → 20 行脚本导出 places.js（可借鉴 NFU 的 example/ 管线）。
图片版权怎么写 优先自己拍 / 官方公众号图（注明来源）/ Unsplash 类免费图。文档里写明"演示用图，正式上线前替换或取得授权"——老师问起来这是加分项，不是减分项。

07

分工

3 人，一人一块，不交叉
ROLE A

地图前端

地图页、路线页、marker / polyline / 气泡、性能调优。

交付：pages/map · pages/routes · components/tag-bar
ROLE B

交互前端

详情页、我的页、打卡、云数据库、全局状态与兜底。

交付：pages/detail · pages/mine · utils/*
ROLE C

数据 + 文档

30→60 个点采集、文案、图片、PPT、演示脚本、README。

交付：data/* · docs/* · 答辩材料

协作规则

  1. 一个 main 分支每天结束前合并，保证当天代码能运行。宁可晚半小时下班，不要留"明天再合"。
  2. 两人不碰同一文件公共文件（app.json / app.wxss / tokens.wxss）改动前先在群里说一声。
  3. 每天 15 分钟站会昨天完成 / 今天目标 / 卡在哪。卡超过半天的事立刻说，不要自己硬扛。
  4. 每天一张真机截图存 docs/screenshots/，最后做 PPT 和录屏直接取材，不用返工。
08

风险与预案

2026-10 核实版，不是网上抄的
风险概率预案
个人主体选不了「旅游-景区服务」类目 确定 本来就不上架。开发版 / 体验版 + 手机投屏答辩；文档写"拟以企业主体上线"。
wx.getLocation 后台申请不下来 高 2022-07 后须在 app.json 声明 requiredPrivateInfos 并在后台「接口设置」申请。个人主体可用「工具-信息查询」类目申请（场景含地理打卡），但能否通过以后台为准——所以手动打卡降级是必做项。
云开发免费环境有坑 中 免费环境活动至 2026-12-31、发布后 15 天到期。先把本地 JSON + storage 跑通，云只做"能上就上"的增强。
主包 2MB 超限 高 图片全部走云存储，包内只留图标和 ≤1 张示例图。
基座代码老旧 / 有 bug 中 1.5 天没改顺就自建，别在别人的烂代码上熬。
marker 太多导致卡顿 中 每分类 ≤15 个；ALWAYS 气泡只给重点位；预留点聚合开关。
抄代码导致软著 / 原创性存疑 中 只用 Apache-2.0 / MIT 并保留声明；无 License 项目只参考。
图片侵权 中 自拍 / 授权图，或明确标注"演示用图"。
队友掉队 中 任务粒度 ≤1 天；D8 功能冻结兜底。
09

验收标准

Definition of Done

功能 · 一条都不能断

  • 真机打开，3 秒内看到湘潭地图和 ≥30 个 marker
  • 六分类切换正确、不卡顿
  • 点 marker → 卡片 → 详情 → 导航，全链路无断点
  • 3 条路线可切换，polyline 与序号正确
  • 允许定位时打卡成功；拒绝定位时可手动打卡
  • 杀进程重进记录仍在，换设备能拉回云端记录

非功能 · 答辩不出丑

  • 主包 < 2MB，冷启动 < 3s
  • iOS + Android 各 1 台真机验证
  • 无网络时友好提示，不白屏
  • 控制台无报错
  • 代码仓库 README：如何导入、如何跑、如何换城市
  • 演示视频 60–90s + PPT 10–12 页 + 500 字项目简介
