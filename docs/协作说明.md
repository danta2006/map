# 多人协作说明（不走 GitHub）

> 背景：本机访问 github.com:443 被墙，但 gitee.com / gitcode.com 可直连。
> 目标：让同事拿到同一份代码、同一套云开发环境，能编译、能上传体验版。

## 一、先分清两种「加入」

| 角色 | 能做什么 | 在哪加 |
|---|---|---|
| **开发成员** | 拉代码、编译、上传体验版、进云开发 | 小程序后台 → 成员管理 → 开发成员（管理员扫码确认） |
| **体验成员** | 只能扫码用体验版，不能看代码 | 小程序后台 → 成员管理 → 体验成员 |

只做演示/试用 → 加「体验成员」+ 发体验二维码就够，**根本不用拉代码**。

要一起写代码 → 往下走 Gitee 方案，并且两个人必须用**同一个 AppID**（`wx8f72fd67cbda3aa9`），因为云开发环境、体验版、成员权限都绑在 AppID 上。

## 二、方案 A（推荐）：Gitee 私有仓库

### 你（项目主）做

1. 注册/登录 [gitee.com](https://gitee.com) → 新建仓库
   - 仓库名 `map`，可见性选**私有**
   - **不要**勾选「使用 Readme 初始化」（避免和本地历史冲突）
2. 本地加远端并推上去（用 Gitee 的私人令牌或账号密码）：

```powershell
cd C:\微信小程序
git remote add gitee https://gitee.com/<你的Gitee用户名>/map.git
git push -u gitee HEAD:main
```

3. Gitee 仓库 → 管理 → **仓库成员管理** → 邀请同事，角色选「开发者」
4. 小程序后台 → 成员管理 → 开发成员 → 添加同事微信号（管理员扫码确认）

### 同事做

1. 安装微信开发者工具，登录自己的微信（已被加为开发成员）
2. 克隆仓库（Gitee 页面「克隆/下载」或命令行）：

```
git clone https://gitee.com/<你的Gitee用户名>/map.git
```

3. 开发者工具 → 导入项目 → 目录选 `map` 文件夹（`project.config.json` 在同一层）→ 确认 AppID 是 `wx8f72fd67cbda3aa9`
4. 直接编译即可。**不需要**配 `admin/.env.local`（那是本机后台用的密钥，不在仓库里）
5. 日常：`git pull` 同步；改完 `git push` 或提 Gitee Pull Request

> 微信开发者工具自带「版本管理」面板，也支持直接连 Gitee：设置 → 版本管理 → 远程仓库填 Gitee 地址即可图形化提交/拉取。

## 三、方案 B（最简单）：只在同一台电脑/局域网共享

- 把 `C:\微信小程序` 整个文件夹放到局域网共享盘，或复制到同事电脑（压缩包）
- 适合「临时演示/同事帮你改一两处」，**多人同时改会冲突**，不要长期用

## 四、哪些文件不能共享 / 不会冲突

仓库里已经用 `.gitignore` 排除了：

| 文件 | 说明 |
|---|---|
| `admin/.env.local` | AppSecret / 高德 Key / 后台令牌，**每人本地各自一份**，不共享、不发群 |
| `_tmp/` | 临时脚本、自动化测试脚本，各人自己用 |
| `project.private.config.json` | 开发者工具的个人配置（窗口、编译设置） |
| `admin/data/feedback.json` | 用户反馈含 openid/联系方式，**不入库**（仓库里只有脱敏样例） |

内容数据（`admin/data/places.json`、`routes.json`、`cities.json`）是共享的，改完导出、提交即可。

## 五、云开发怎么共用

- 云开发环境跟着 **AppID** 走，同一 AppID 的开发成员登录开发者工具后，能直接看到并用 `cloud1-d5ghzdcqba4c291f8`
- 云函数部署/数据库操作：同一 AppID 的开发者一般都有权限；如果提示无权限，让管理员在小程序后台确认成员角色
- 云函数代码在仓库 `cloudfunctions/` 里，谁改了谁部署（命令见 `docs/交接说明.md`）

## 六、协作节奏建议

1. `main` 分支保持可运行，只有你和被授权的同事能合
2. 同事从 Gitee clone 后开自己的分支（如 `dev-xiaoming`），改完提 PR
3. 每次演示前：你统一合并、跑 `node scripts/check_pages.js`、上传新体验版
4. 大文件（图片、PDF）已在仓库里，注意别把 `docs/screenshots` 再翻倍；新截图随手压缩

## 七、常见坑

| 坑 | 解决 |
|---|---|
| 同事打开项目提示 AppID 不对/无法编译 | 导入时用 `project.config.json` 里的 `wx8f72fd67cbda3aa9`，且他已被加为开发成员 |
| 同事改了代码但云函数没生效 | 云函数要单独部署（`cli cloud functions deploy ...`），不是编译就能上 |
| 同事运行后台报缺密钥 | `admin/.env.local` 不在仓库里，各自按 `admin/.env.local.example` 填 |
| 两人同时改同一个 wxml 冲突 | 每次开工先 `git pull`，改完早提交；冲突时保留双方逻辑再跑 `check_pages.js` |
| 体验版二维码过期 | 管理员重新上传体验版即可续期 |
