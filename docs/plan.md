## 0. 一页结论

| 项 | 决策 |
|---|---|
| 做什么 | 一张湘潭地图，每个点可点开看攻略；3 条精选路线可沿线逛；到点可打卡，形成"足迹" |
| 不做什么 | 社区/UGC、评论、支付、多城市、后台管理系统、真实用户运营、个性化地图 |
| 技术栈 | **微信原生小程序（JS）+ 内置 map 组件**，不上 Taro/uni-app，不上构建链 |
| 数据 | POI 打包成本地 `data/places.js`（零延迟、免分页）；图片放**云存储**；打卡记录放**云数据库** |
| 后端 | **云开发，但零云函数**：数据库"仅创建者可读写"自动带 openid，客户端直连即可 |
| 复用基座 | [map-marker-miniprogram](https://github.com/Volcano-Yang/map-marker-miniprogram)（Apache-2.0，纯原生标点模板，87★）为主；[LYWL](https://github.com/Rin-Ling/LYWL) 只做产品参考；[wetour](https://github.com/Mayandev/wetour) 参考打卡 |
| 规模 | 5 个页面 + 2 个组件；30 个点（冲刺 60）+ 3 条路线 |
| 成功标准 | 真机（开发版）打开 → 地图有 30 个点 → 筛选/点开/详情/导航全部可用 → 路线能看 → 打卡能记 |

### 开工前先知道三个坑
- **类目**：个人主体选不了「旅游-景区服务」，别指望上架；开发版 / 体验版 + 投屏答辩。
- **定位**：`wx.getLocation` 要在后台申请、可能不批；手动打卡降级是必做项。
- **包体**：主包 2MB，60 张图必超；图片全部走云存储。

> 阅读路径：决策看 01–02；开发看 03–05；推进看 06–08；验收看 09–10。

## 1. 产品定义

**一句话**：把湘潭的景点、美食、老街，从"一篇文章"变成"地图上一个个能点开的点"，再串成能照着走的路线。

- **对标**：截图里的十六番 / 懒人地图式「标点地图」——地图即首页，点开即内容。
- **使用场景**：外地学生/游客落地湘潭，打开小程序 → 看地图 → 选路线 → 按点逛 → 打卡留痕。
- **大创要讲的创新点**（答辩选 2 个讲透即可）：
  1. **地图即入口**：用空间关系组织内容，替代传统"图文列表"式攻略；
  2. **路线化内容**：不是 POI 堆砌，而是"老城湘江线 / 红色韶山线 / 学府新城线"三条可执行动线；
  3. **打卡足迹**：把观光行为游戏化，形成可展示的个人足迹地图；
  4. **在地青年视角**：每个点配一条"本地人提示"（何时去、避什么坑），这是机器攻略给不了的。

## 3. 技术方案

### 3.1 技术栈
```
微信原生小程序（WXML/WXSS/JS）
├─ 不引入 Taro / uni-app / wepy        ← 12 天不够踩框架坑
├─ 不引入 npm 构建链                    ← 少一类"编译失败"故障
├─ 地图：内置 <map>
│   ├─ markers（分类图标 + 自定义气泡）
│   ├─ polyline（路线）
│   └─ wx.openLocation（导航）
├─ 数据：/data/places.js、/data/routes.js（纯 JS 模块，require 即用）
├─ 云：云开发数据库（仅打卡记录）+ 云存储（图片）
├─ 状态：/utils/store.js（简易全局状态 + wx.storage 兜底）
└─ 样式：/styles/tokens.wxss（颜色/字号/间距，全项目只用这一套变量）
```

**为什么不做个性化地图**：自 2023-06-29 起 subkey 需在 MP「付费管理」购买配置、工具内不能调试、必须真机验证。默认样式 + 自绘 marker 已经够好看，别给自己找麻烦。

### 3.2 关键实现要点
- **marker 气泡**：用 `<cover-view slot="callout" marker-id="{{id}}">` + `markers[].customCallout`（基础库 2.12.0+）。**不要给 30 个点全开 ALWAYS**，会糊成一片；首页最多 3–5 个重点位开 ALWAYS，其余 `BYCLICK`。
- **筛选**：按 category 预生成 5 组 markers 数组缓存，切换直接 setData，不重新算。
- **搜索**：**本地过滤 `places.js`，绝不调腾讯地点搜索 API**（免费额度每日仅 200 次，且要配合法域名）。
- **路线 polyline**：坐标串**离线生成一次**存 `routes.js`，运行时零 API 调用。手绘 8–12 个拐点也够看，不必接路线规划。
- **打卡判定**：`wx.getLocation({type:'gcj02'})` → 15 行 haversine 算距离 → `< 500m` 允许打卡。失败/拒绝时，按钮降级为「我到过这里（手动打卡）」——**答辩现场兜底就靠它**。
- **云开发怎么做到零云函数**：
  - `checkins` 集合权限设为「仅创建者可读写」→ 用户查询只返回自己的记录，且写入自动带 `_openid`；
  - `places` 不需要建集合（本地 JSON）；
  - 图片上传云存储，`<image src="cloud://...">` 直接可用，无需配置域名。
  - **兜底**：`utils/db.js` 里如果 `wx.cloud` 调用失败，打卡写 `wx.storage`，我的页合并展示。演示断网也不翻车。

### 3.3 页面结构（5 页 + 2 组件）
```
pages/
├─ map/          地图首页（tab1，核心，占 40% 工作量）
├─ routes/       路线页（tab2）
├─ mine/         我的/足迹（tab3）
├─ detail/       点位详情（非 tab）
└─ route-detail/ 单条路线详情（非 tab，地图模式）
components/
├─ poi-card/     POI 卡片（地图底部卡片、列表复用）
└─ tag-bar/      分类筛选条（可复用）
```
> 只做 3 个 tab。第四个 tab（发现/攻略）不做——和地图内容高度重复，砍掉不影响演示。

### 3.4 关键技术取舍（写进文档，答辩可讲）
| 问题 | 方案 | 理由 |
|---|---|---|
| 图片放哪 | **云存储** + 压缩到 150KB/张 | 主包 2MB 上限，60 张图必然超限；云存储免域名配置 |
| POI 数据放哪 | **本地 JSON 打包**（60 条 ≈ 50KB） | 零延迟；客户端查库默认只回 20 条，60 条要分 3 页，纯属自找麻烦 |
| 打卡存哪 | 云数据库 `checkins`（仅创建者可读写） | 换设备不丢；自动 openid；免登录、免云函数 |
| 路线折线哪来 | 离线生成 → 静态 JSON | 免配额、免域名 |
| 地图样式 | 默认样式 + 自绘 marker | 个性化地图要付费购买，且只能真机调试 |
| 登录 | 不强制，云开发自动 openid | 省掉 code2Session、隐私协议、审核 |

### 4.2 具体"拿什么"（基座适配清单）
以 map-marker-miniprogram 为基座，改动如下：

| 动作 | 位置 | 说明 |
|---|---|---|
| 改配置 | `miniprogram/config.js` | `center_longitude/latitude` → 湘潭（约 112.94 / 27.85）、`appName`、`envID`、`default_scale` 调 11–12 |
| 换数据源 | `pages/map/map.js` 的 `getMarkerData` | 把 `wx.cloud.callFunction({name:'getStore'})` 换成 `require('../../data/places.js')`；`problemLabel` 三分法 → 六分类 |
| 换分类 | 同文件 | 盲道三分类 → 景点/美食/古镇/红色/学府 |
| 复用详情页 | `pages/info` | 改字段绑定即可当景点详情；加上"导航""打卡""本地提示" |
| 复用列表/搜索 | `pages/allList`、`pages/search` | 列表页 = 路线点位列表；搜索页改本地过滤 |
| **砍掉** | `pages/add`、`pages/share`、`painter/`、`components/shareBox`、`cloudfunctions/*` | 上传/海报/分享/管理员都不做，删掉能省 500KB+ 和一堆坑 |
| 修 bug | `map.js:83` | `if (res.result.errMsg = "ok")` 是赋值不是比较，顺手修 |
| 换废弃 API | `map.js:270` | `wx.getUserProfile` 已废弃 → 删除登录逻辑，直接用 openid |

> 如果适配过程超过 1.5 天，**果断放弃基座、按本方案自建**（自建 5 个页面约 1500 行，AI 辅助 2 天能出）。基座是省时间的，不是供起来的。

### 5.3 字段设计（`data/places.js`）
```js
{
  id: 'wanlou',
  name: '万楼',
  category: 'scenic',            // scenic/food/oldtown/red/school
  tags: ['地标', '夜景'],
  lat: 27.8712, lng: 112.9445,   // 必须 GCJ-02，和地图组件一致
  cover: 'cloud://xxx/wanlou.jpg',
  summary: '一句话（≤30 字，卡片显示）',
  intro: '80–120 字简介',
  localTip: '本地人提示（"傍晚去，江风+灯光最好"）',
  address: '湘潭市雨湖区…',
  openTime: '08:00-18:00 / 全天',
  durationMin: 60,
  routeIds: ['oldtown']
}
```

### 5.4 采集流程
1. **定名单**（0.5 天）：按 5.2 确认 30 个 P0 点。
2. **拿坐标**（0.5 天）：腾讯位置服务「[坐标拾取器](https://lbs.qq.com/getPoint/)」手工点，30 个约 1.5 小时，最稳。**不要在小程序里调地点搜索 API**（200 次/日）；要脚本就写个本地 Node 脚本调 WebService。
3. **写文案**（1.5 天）：每人 10 个点，按模板填。**文案质量决定答辩观感**，别抄百科。
4. **配图**（1 天）：统一裁 4:3、压到 150KB 内，传云存储；`places.js` 里只存 fileID。
5. **转 JSON**（0.5 天）：用 Excel 维护 → 一个 20 行脚本导出 `places.js`（可直接借鉴 NFU 的 `example/` 管线）。

### 5.5 图片版权
优先自己拍 / 官方公众号图（注明来源）/ Unsplash 类免费图。文档写明"演示用图，正式上线前替换/授权"——老师问起来这是加分项。

## 8. 风险与预案（2026-10 核实版）

## 9. 验收标准（Definition of Done）

**功能**
- [ ] 真机打开，3 秒内看到湘潭地图和 ≥30 个 marker
- [ ] 六分类切换正确、不卡顿
- [ ] 点 marker → 卡片 → 详情 → 导航，全链路无断点
- [ ] 3 条路线可切换，polyline 与序号正确
- [ ] 允许定位时打卡成功；拒绝定位时可手动打卡
- [ ] 杀进程重进，打卡记录仍在（且换设备能拉回云端记录）

**非功能**
- [ ] 主包 < 2MB，冷启动 < 3s
- [ ] iOS + Android 各 1 台真机验证
- [ ] 无网络时友好提示，不白屏
- [ ] 控制台无报错

**交付物**
- [ ] 代码仓库（README：如何导入、如何跑、如何换城市）
- [ ] 演示视频 60–90s
- [ ] PPT 10–12 页（痛点 / 方案 / 技术 / 数据 / 创新点 / 演示 / 展望）
- [ ] 500 字项目简介（大创申报用）
